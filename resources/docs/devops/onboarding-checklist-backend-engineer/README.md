# Backend Engineer Onboarding Checklist — Companion Resources

Companion files for the [Backend Engineer Onboarding Checklist](https://stackpractices.com/docs/onboarding-checklist-backend-engineer/) on StackPractices.com.

## What's included

| File | Format | Description |
|------|--------|-------------|
| `onboarding-checklist.md` | Markdown | The fillable two-week checklist: Day 1 setup, Week 1 codebase orientation, Week 2 production awareness and ownership, completion verification table, and feedback section |
| `30-60-90-plan.txt` | Text | The quarter-long plan with goals and check-ins at day 30 (contributing), 60 (owning), and 90 (independent) |
| `onboarding-checklist-frontend-variant.md` | Markdown | Diff-only adaptations for frontend and QA engineer roles (environment, orientation, and production sections) |

## Quick start

### 1. Adapt before the hire starts

Swap the generic items for real ones — actual repo names, Slack channels, dashboards, tooling versions. A checklist that names things gets used; placeholders get skimmed once.

### 2. Assign the three roles

The manager owns the outcome (check-ins, unblocking). The buddy owns the day-to-day ("how do I..." questions, first PR). The new hire owns the checklist and the feedback section.

### 3. Pre-stage day one

Hardware shipped early, accounts provisioned and tested, a buddy with real sprint capacity, and a trivial first PR pre-picked — the day's goal is a merged PR, not a tour.

### 4. Close the loop

Verify each area in the completion table (someone watched it happen, not just ticked), run the day-30/60/90 check-ins, and update the checklist within a week of each hire finishing — while feedback is fresh.
