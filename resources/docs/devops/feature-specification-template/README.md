# Feature Spec Template — Companion Resources

Fillable feature specification template in Markdown, plus a complete worked example.

## Files

- `feature-specification-template.md` — the blank spec: summary, goals and non-goals, user stories, functional and non-functional requirements, design/UX, technical approach and rollout, acceptance criteria, open questions, an approvals table, and a changelog field.
- `example-filled.md` — the same template completed for a fictional real-time order notifications feature, showing goals with numbers, testable requirements, and a filled approvals table.

## How to use

1. Copy `feature-specification-template.md` into your repo, wiki, or a ticket.
2. Draft every section except the summary; write the summary last, once the rest is clear.
3. Review it with product, engineering, and design in one meeting; fill the approvals table with an explicit yes or no from each discipline.
4. When scope changes, update the spec and log the change in the changelog field — a living spec beats a perfect spec that goes stale.
5. To feed the spec to an AI coding agent, keep the numbered requirements and binary acceptance criteria — agents implement what the document literally says.
