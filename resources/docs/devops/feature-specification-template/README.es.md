# Plantilla de Especificación de Funcionalidad — Recursos Complementarios

Plantilla rellenable de especificación de funcionalidad en Markdown, más un ejemplo completado.

## Archivos

- `feature-specification-template.md` — la spec en blanco: resumen, objetivos y no objetivos, historias de usuario, requisitos funcionales y no funcionales, diseño/UX, enfoque técnico y rollout, criterios de aceptación, preguntas abiertas, tabla de aprobaciones y registro de cambios.
- `example-filled.md` — la misma plantilla completada para una funcionalidad ficticia de notificaciones de pedido en tiempo real, con objetivos medibles, requisitos verificables y la tabla de aprobaciones rellenada.

## Cómo usarla

1. Copia `feature-specification-template.md` a tu repo, wiki o ticket.
2. Redacta todas las secciones menos el resumen; escribe el resumen al final, cuando el resto esté claro.
3. Revísala con producto, ingeniería y diseño en una reunión; rellena la tabla de aprobaciones con un sí o un no explícito por disciplina.
4. Cuando cambie el alcance, actualiza la spec y registra el cambio — una spec viva gana a una spec perfecta que envejece.
5. Para alimentar con la spec a un agente de código IA, conserva los requisitos numerados y los criterios de aceptación binarios: los agentes implementan lo que el documento dice literalmente.
